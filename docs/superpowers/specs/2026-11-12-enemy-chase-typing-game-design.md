# 拼音追逃：手机浏览器无尽打字追逐游戏设计规格

- 日期：2026-11-12
- 状态：已确认，可进入实现计划
- 工作名称：拼音追逃

## 1. 产品目标

制作一款可在手机浏览器直接游玩的无尽打字追逐小游戏。玩家扮演被敌人追赶的小冒险家，在一条不断延伸、弯曲的平面迷宫中逃跑。屏幕同时展示中文句子和无声调拼音提示，玩家使用手机原生键盘照着输入拼音字母；每输入正确一个字母，主角沿迷宫前进一格，错误输入则令主角停顿、敌人迅速逼近。

游戏不设最终关。每到达终点门后进入新的、更难的关卡；难度同时提升敌人速度、题目长度与生僻程度、迷宫弯道数量。游戏强调紧张、即时、直观的反馈，适合短时连续挑战。

## 2. 目标用户与场景

- 使用手机浏览器、习惯中文拼音输入的玩家。
- 单手持机、竖屏游玩为主，单局从数十秒到数分钟。
- 无需账号或网络服务，打开静态网页即可开始。
- 用户可能使用中文输入法、英文键盘或系统当前默认键盘；游戏不得绘制自制键盘。

## 3. 目标与非目标

### 3.1 目标

- 提供“逐字母推进”的真实打字追逐手感。
- 使用原生 DOM 输入框唤起手机系统键盘。
- 用长而弯曲的单线迷宫表现持续逃跑，并让镜头跟随主角。
- 提供简单、普通、困难、极限四档难度。
- 支持无尽关卡和逐关上升的综合难度。
- 用高对比卡通形象、动画、音效和震动强化紧迫感。
- 在本机保存最高关卡，刷新页面后仍可读取。

### 3.2 非目标

- 不做登录、注册或云存档。
- 不做排行榜、好友系统或社交分享。
- 不做内购、广告、体力或任何商业化系统。
- 不做复杂剧情、角色养成或地图选择。
- 不做多人模式、实时对战或服务器端判定。
- 不做自制屏幕键盘。
- 不做分支迷宫或手动转向；迷宫是连续单线路径。

## 4. 核心玩法

### 4.1 游戏流程

1. 标题页展示玩法说明、四档难度、各难度打字记录和本机最高关卡。
2. 玩家选择难度并点击开始。
3. 游戏进入第一关，系统自动聚焦真实输入框并唤起原生键盘。
4. 屏幕显示当前中文句子及其完整、无声调拼音提示。
5. 玩家逐字母输入拼音。正确字母推进主角；错误字母触发惩罚。
6. 完成当前句子后自动切换下一句，主角继续沿迷宫前进。
7. 主角到达终点门后进入下一关，生成新的更长、更弯的迷宫和更难的题目。
8. 敌人追上主角时本局结束，展示到达关卡并提供重新开始或更换难度。
9. 游戏没有最终关；一直闯关，直到玩家失败或主动退出。

### 4.2 主角移动

- 主角只在输入正确字母时向前推进；每次正确输入对应一个固定世界距离的“字母步”。
- 主角沿迷宫中心线运动，视觉位置在离散目标之间平滑插值，避免瞬移。
- 连续输入正确时，主角保持跑步动画，并产生轻微速度线和路径点亮效果。
- 输入错误后，主角停止推进 `250ms`，再恢复接受正确输入。

### 4.3 敌人追击

- 敌人位于主角后方同一条迷宫中心线上，始终保持追击姿态。
- 敌人按当前难度的基础速度持续前进，即使玩家没有按键也会逐渐靠近。
- 输入错误时，敌人立即额外前进一个“扑击距离”，并播放夸张扑近动画。
- 当敌人与主角的距离小于等于零并持续 `500ms` 时判定被追上，本局结束。
- 主角正确输入产生的推进速度可以拉开距离；停止或频繁出错会缩短距离。
- 关卡切换时敌人退场，下一关在后方以基础追击距离重新出现。

### 4.4 输入判定

- 题目区同时显示中文和完整、无拼音声调符号的拼音提示；`ü` 在提示中显示为常用输入形式 `v`，例如“绿色 / lv se”。
- 玩家照拼音提示输入；判定按字母逐个进行，不使用整句提交。
- 比较前执行归一化：
  - 转为小写。
  - 忽略空格、标点、数字、声调符号和其他非字母字符。
  - 将 `ü`、`u:` 和输入字母 `v` 统一为 `v`；提示中统一显示 `v`，玩家直接输入 `v`。
  - 忽略中文输入法组合过程中不应计入候选汉字的控制字符。
- 正确输入推进一格并将输入游标前移。
- 错误输入不移动游标、不保存错误字符，触发停顿、敌人扑近、画面泛红、错误音效和可用时的震动。
- 退格不能撤销已获得的移动进度；退格键本身不计为错误。
- 输入焦点丢失后，玩家点击游戏画面或题目区即可重新唤起原生键盘。
- 当前句子完成后，游标归零并自动加载下一句；关卡结束前不要求额外确认。

### 4.5 原生键盘实现约束

- 使用真实的 `<input type="text">`，设置 `autocapitalize="none"`、`autocomplete="off"`、`autocorrect="off"`、`spellcheck="false"`。
- 输入框视觉上融入题目卡片，但不渲染任何自制键盘按键。
- 同时处理普通 `beforeinput`/`input` 字母输入与中文输入法 `compositionstart`、`compositionupdate`、`compositionend` 组合输入，避免同一拼音字母被重复消费。
- 系统键盘弹出时通过 `visualViewport` 更新可用高度；游戏画布缩放到剩余空间，题目和输入框保持可见。
- 点击开始按钮必须发生在用户手势内，以便同时激活输入框和音频。

## 5. 关卡与难度

### 5.1 难度选择

难度在每局开始前固定选择，游戏过程中不动态改变档位。

| 参数 | 简单 | 普通 | 困难 | 极限 |
| --- | --- | --- | --- | --- |
| 初始敌人速度 | 1.4 字母步/秒 | 2.2 字母步/秒 | 3.0 字母步/秒 | 4.2 字母步/秒 |
| 每关敌人速度增量 | +0.08 | +0.12 | +0.16 | +0.22 |
| 初始敌人距离 | 14 字母步 | 11 字母步 | 8 字母步 | 6 字母步 |
| 初始题目档位 | 1 | 2 | 4 | 5 |
| 每关句子数量 | 3 | 4 | 5 | 6 |
| 题目层级公式 | `min(5, 1 + floor((level-1)/4))` | `min(5, 2 + floor((level-1)/4))` | `min(5, 4 + floor((level-1)/4))` | `5` |
| 迷宫弯道公式 | `5 + min(level-1, 12)` | `7 + min(level-1, 12)` | `9 + min(level-1, 12)` | `13 + min(level-1, 12)` |

敌人速度公式为 `基础速度 + (level - 1) * 每关增量`。以上数值为初始平衡目标，最终在真机试玩中微调，但难度必须随关卡单调上升。

### 5.2 无尽难度曲线

- 每进入新关，敌人基础速度按难度增量提高。
- 题目从短句逐步变为长句，词汇从常用词逐步进入低频词和生僻词。
- 每关通常完成 3 / 4 / 5 / 6 个完整句子；单关时长主要由句子长度增加决定。
- 每关的迷宫总长度等于该关全部题目归一化拼音字母数之和；每正确输入一个字母推进一个字母步，完成最后一句时正好抵达终点门。
- 迷宫弯道数和弯道紧凑度提高；弯道数量增长 12 关后稳定在高位，但题目生僻度、长度和敌人压力继续增长。
- 难度没有预设终点，也不设置可通关的最终关。

### 5.3 题库

- 题目采用本地静态题库，至少包含 5 个难度层级、总计不少于 120 条完整中文句子。
- 每条题目包含：中文文本、无声调拼音、音节数、难度层级。
- 题库从简单完整的日常句子开始，逐层增加句子长度、从句、生僻字和低频表达。
- 第 1 层句子约 10–20 个汉字，第 3 层约 24–35 个汉字，第 4–5 层约 35–55 个汉字。
- 同一局中优先避免短期重复；题库耗尽后允许按难度重新洗牌。
- 所有拼音必须在实现时人工或自动校验，确保提示与汉字读音一致。

### 5.4 实时打字统计与难度记录

- HUD 实时显示当前 CPM（每分钟正确输入字母数）和当前正确率。
- CPM 使用最近 5 秒的正确输入字母数换算；暂停和切后台时间不计入活跃时间。
- 单局活跃时间达到 2 秒后，才允许刷新历史最高 CPM，防止开局单次输入造成虚高。
- 简单、普通、困难、极限分别保存：历史最高 CPM、累计输入字符数、正确输入字符数。
- 累计输入字符数包含正确和错误按键；正确率由正确字符数除以累计输入字符数计算。
- 开始界面的四张难度卡分别展示对应记录。

## 6. 迷宫设计

- 迷宫为俯视平面单线通道，不设分支和方向选择。
- 路径由一组带种子的曲线节点生成，形成长距离 S 弯、回环和窄通道。
- 主角和敌人均沿中心线移动；镜头围绕主角平滑跟随，并提前展示前方一段路径。
- 终点门位于关卡路径末端，持续发出脉冲光。
- 弯道增加会让镜头摆动更明显、前方可见距离更短，但不改变逐字母输入规则。
- 每关使用确定性种子，便于测试重现；同一次重试不需要固定同一迷宫。
- 路径必须闭合绘制为可行走通道，不能出现断裂、交叉混淆或把终点画到不可达位置。

## 7. 视觉设计

### 7.1 总体风格

- 高对比“霓虹追逐卡通”风格。
- 主色：
  - 深墨蓝背景：`#071426`
  - 荧光黄路径：`#DDF247`
  - 珊瑚红敌人：`#FF4D4D`
  - 青色终点门：`#32E6D4`
  - 米白文字：`#FFF6D8`
- 画面信息层级必须保证手机小屏一眼可辨，不依赖细线或低对比颜色。
- 竖屏优先，兼容横屏；适配刘海和底部安全区。

### 7.2 主角

- 小冒险家形象：大围巾、小背包、夸张眼睛、慌张但坚定的表情。
- 体型较小，轮廓明亮，与敌人形成明显尺寸差。
- 跑步时身体前倾、双腿快速交替、围巾拖曳；正确连击时围巾和路径发光。

### 7.3 敌人

- 巨型墨团追猎怪：锯齿轮廓、发光眼睛、伸缩触手或巨掌。
- 体型显著大于主角，颜色更重、更有压迫感。
- 追击时身体挤压拉伸；玩家出错时向前扑击并放大局部表情。
- 被拉远时仍保持可见的威胁提示，避免玩家失去距离感。

### 7.4 界面布局

- 顶部 HUD：关卡、难度、敌人距离、静音按钮。
- 中部主画布：弯曲迷宫、主角、敌人和终点门。
- 下部题目卡：中文句子、拼音提示、已输入/待输入状态、真实输入框。
- 系统键盘弹出后，主画布自动压缩，题目卡和输入框保留完整。
- 游戏结束覆盖层：到达关卡、本机最高关卡、“再来一次”和“更换难度”。“再来一次”从同一难度的第 1 关重新开始。

### 7.5 动画与反馈

- 正确输入：短促高音、脚印/粒子、路径前方点亮。
- 错误输入：红色边缘闪烁、画面轻微抖动、主角停顿、敌人扑近。
- 敌人逼近：背景速度线增强，音乐节奏加快。
- 抵达终点：门爆发扩散光环，短暂庆祝后无缝进入下一关。
- 被追上：敌人盖住画面，游戏结束覆盖层滑入。
- 尊重 `prefers-reduced-motion`；开启时减少镜头抖动和大幅位移，但保留颜色与文字反馈。

## 8. 音效与触觉

- 使用 Web Audio 或紧凑本地音频资源，首次点击后启动。
- 正确输入使用轻快短音；连续正确时音高可轻微上升。
- 错误输入使用短促低频提示音。
- 敌人逼近时音乐或脉冲节奏加快。
- 提供静音开关，并保存本机静音偏好。
- Android 等支持 `navigator.vibrate` 的设备在错误时触发 `20-35ms` 短震动；不支持时静默降级。
- iOS 不支持震动 API 时不得报错，依靠视觉与音效反馈。

## 9. 数据与本机存储

- 最高关卡（进入过的最高关卡编号）、本局最远距离、所选难度和静音状态存储于 `localStorage`。
- 不收集姓名、账号、位置或任何个人数据。
- 存储键统一使用 `pinyin-chase:*` 前缀。
- 若 `localStorage` 不可用，游戏继续运行，仅使用内存保存本局状态，并在界面中不提示技术错误。

存储结构：

```ts
type DifficultyStats = {
  bestCpm: number;
  totalLetters: number;
  correctLetters: number;
};

type PersistedProgress = {
  bestLevel: number;
  bestDistance: number;
  lastDifficulty: "easy" | "normal" | "hard" | "extreme";
  muted: boolean;
  stats: Record<"easy" | "normal" | "hard" | "extreme", DifficultyStats>;
};
```

## 10. 技术架构

### 10.1 技术栈

- Vite
- TypeScript
- Canvas 2D
- 原生 DOM/CSS
- Vitest
- Playwright

不使用前端框架、后端、数据库或运行时网络 API。

### 10.2 模块边界

- `app shell`：标题页、难度选择、游戏页、结束页和全局可达性控制。
- `game state`：状态机、关卡数据、主角/敌人位置、输入游标和胜负条件。
- `game loop`：固定时间步更新逻辑，独立于渲染帧率。
- `input adapter`：管理真实输入框、原生键盘、组合输入和字母事件归一化。
- `pinyin engine`：拼音归一化、逐字母比较、句子推进。
- `phrase bank`：分级题库和选题策略。
- `maze generator`：按种子生成单线弯曲路径、墙体、门和总长度。
- `difficulty progression`：根据难度和关卡计算敌人速度、题长、生僻度和弯道参数。
- `canvas renderer`：绘制迷宫、角色、镜头、粒子、速度线和转场。
- `audio/haptics`：Web Audio、震动能力和静音状态。
- `persistence`：本机最高进度和偏好读写。

各模块通过明确的数据对象通信；渲染层不负责游戏判定，输入层不直接修改 Canvas 状态。

### 10.3 游戏状态机

状态包括：

- `menu`：选择难度和开始。
- `playing`：正常游戏与输入。
- `paused`：页面隐藏或输入焦点丢失导致的暂停。
- `levelClear`：到达终点门的短转场。
- `gameOver`：被敌人追上。

合法事件包括开始、正确字母、错误字母、完成句子、抵达终点、进入下一关、暂停、恢复、重试和更换难度。任何状态下都必须保证输入游标与画面状态一致。

### 10.4 数据流

1. 原生键盘事件进入输入适配器。
2. 输入适配器提取新增字母并交给拼音引擎。
3. 拼音引擎返回 `correct`、`wrong` 或 `ignored`。
4. 游戏状态机根据结果推进主角、触发敌人扑近、切换题目或结束游戏。
5. 渲染器读取只读游戏快照绘制画面。
6. 音频、震动、HUD 和本地存储根据状态变化产生反馈。

### 10.5 迷宫坐标与运动

- 迷宫路径先由控制点生成，再采样为等距中心线点。
- 主角/敌人的世界位置映射到中心线距离，不使用自由二维导航。
- 正确字母对应固定中心线距离，视觉位置通过插值靠近逻辑目标。
- 相机目标为主角当前位置前方一小段，使前进方向始终可见。
- 敌人速度以“字母步/秒”配置，最终换算为同一世界距离单位。

## 11. 异常与兼容处理

- 系统键盘未弹出：点击题目或画布重新聚焦输入框。
- 输入法组合导致重复字母：按输入批次和已消费内容去重，不得重复推进。
- 非拉丁字符、表情和控制字符：忽略且不判定为错误。
- 页面切后台：立即暂停游戏与计时，返回后显示继续提示。
- 音频被浏览器阻止：等待用户再次点击后恢复，不阻塞游戏。
- 高 DPR 设备性能不足：渲染倍率最高限制为 `2`，必要时降低粒子和速度线数量。
- 屏幕旋转或键盘高度变化：重新计算画布尺寸和安全区，不重置游戏进度。
- 存储损坏：捕获解析错误并回退到默认进度。
- 迷宫生成异常：重试同一关的新种子；连续失败时使用安全直线路径兜底。

## 12. 测试与验收

### 12.1 单元测试

- 拼音归一化：大小写、空格、声调、`ü`、`u:`、`v` 和忽略字符。
- 逐字母判定：正确推进、错误不推进、忽略字符、句子切换。
- 退格不撤销移动进度。
- 敌我距离、错误扑击、追击和被捕判定。
- 难度公式在四档下随关卡单调上升。

## 13. 成功标准

- 玩家无需阅读长说明即可理解“照着拼音输入，答对前进，答错被追近”。
- 输入使用手机系统键盘，没有任何自制键位。
- 每按对一个字母都有即时、清晰的前进反馈。
- 错误输入同时表现为停顿、敌人靠近、视觉/音效反馈。
- 四档难度有明显手感差异，且每档均可通过熟练输入持续闯关。
- 迷宫足够长且弯曲，镜头跟随流畅，不产生方向迷失或路径断裂。
- 关卡可无限生成，难度持续上升，没有预设终点。
- 无登录、无排行榜、无内购、无剧情干扰。
- 刷新后保留最高关卡；无后端依赖。
